# Referencia del reto anterior

## Fuente revisada

Repositorio: [Reto Desarrollo Web — Evaluación Basada en Riesgo](https://github.com/AshFranco/Reto-Desarrollo-Web-Evaluacion-Basada-en-Riesgo).

La revisión de lectura corresponde al commit `8cea6488ac8d6fabd374c276e5f37d8bbe136a4a`. El proyecto desarrolla una PWA EBR/BPM de DIGEMAPS con API NestJS/Prisma, web React/TypeScript/MUI, PostgreSQL y un motor de riesgo compartido.

Se estudiaron organización, contratos, planificación, código y documentación de calidad. No se ejecutaron nuevamente la aplicación ni sus pruebas.

## Aprendizajes aplicables

| Observación | Aplicación al reto PEI-POA |
|---|---|
| La encuesta interna define cinco áreas de trabajo y aclara que no forma parte del SRS | Recoger habilidades, interés y disponibilidad sin confundir al equipo con los roles del sistema |
| Las historias enlazan RF, aceptación y prioridad | Mostrar propósito, entregable, pasos y evidencia en cada tarea |
| Los contratos identifican productores, consumidores y estado de revisión | Acordar formatos y dependencias para trabajar en paralelo |
| La revisión de aceptación la hace otra persona | Separar responsable y revisor antes de cerrar la tarea |
| Los hallazgos distinguen defectos de ambigüedades | Conservar preguntas y decisiones con su fuente y efecto |
| La interfaz diferencia guardado, sincronización pendiente y error | Confirmar los cambios y permitir recuperar el trabajo |
| La documentación incluye información de distintas etapas | Mantener un estado vigente y fechar los resultados históricos |

Las prioridades P0/P1/P2 y las definiciones Ready/Done pertenecen al proceso documentado de ese equipo. Sirven como referencia y no se atribuyen automáticamente al docente como obligaciones de este proyecto.

## Límites de la comparación

El flujo EBR es ficha, riesgo y programación de inspección. SISPLAN debe resolver PEI, POA, productos, actividades, avances, evidencias y evaluaciones. No se trasladan fórmulas de riesgo alimentario, inspecciones BPM, frecuencias, trabajo sin conexión ni tickets QR al nuevo alcance.

Las cifras de pruebas del otro repositorio son históricas. Tampoco se considera aplicada una protección de rama solo porque el README la declare: durante la revisión, la rama devolvía `protected:false`.

La referencia permite adoptar una forma de organizar y comprobar el desarrollo; el alcance de SISPLAN sigue definido por su consigna, su SRS y las ampliaciones registradas.
